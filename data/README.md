# Data package

Everything under `data/` is **generated or downloaded by the pipeline** and is git-ignored.
Run `make data` (or `make all`) to recreate it byte-for-byte from `(code commit, config, seed)`.

## Layout

| Folder | Written by | Contents |
|---|---|---|
| `raw/` | `sensecast generate` | Feeds as a retailer would receive them (see dictionary below) |
| `external/` | weather loader | Cached Open-Meteo pulls (`weather_openmeteo.parquet`) |
| `processed/` | `sensecast ingest` | Validated Parquet + `manifest.json` (SHA-256 of every file, data-quality report) |
| `quarantine/` | `sensecast ingest` | Rows that broke a data contract, with the failing `reason` |
| `ground_truth/` | `sensecast generate` | True demand and effect sizes. **Only the evaluator and simulator read this. No model or feature does** (enforced by the leakage tests). |

## Provenance and permissions

| Source | Origin | Licence / permission |
|---|---|---|
| Sales, inventory, items, stores, promotions | Synthetic generator `src/sensecast/generate/world.py` | Generated by this project (MIT) |
| Weather | Open-Meteo historical archive API for Mumbai, Pune and Nashik; falls back to a synthetic climatology calibrated to monthly normals when offline | Open-Meteo data CC BY 4.0, free non-commercial tier. Synthetic fallback: MIT |
| Public holidays | `holidays` Python package (India) | MIT |
| Regional festivals | Curated in `src/sensecast/generate/events.py` (Ganesh Chaturthi, Navratri, Raksha Bandhan, Eid al-Fitr, Gudi Padwa, Makar Sankranti) | Public calendar facts; verify future years against an official panchang |
| Search interest | Generated index per category (a latent "buzz" process that leads demand by 5 days) | Generated. Google Trends is deliberately not scraped: unofficial API, rate limits, terms of service |

No personal data exists anywhere in the system: sales are item x store x day aggregates.

## Versioning

`processed/manifest.json` stores a SHA-256 hash for every raw and processed file plus the
generation summary. Every MLflow run logs the config hash, so any metric can be traced to the exact
data snapshot and configuration that produced it.

## Data dictionary

### raw/sales.parquet (one row per store x item x day, from launch date)
| Column | Type | Unit | Meaning |
|---|---|---|---|
| date | date | day | Business day |
| store_id | str | `S01`..`S10` | Store |
| item_id | str | `I001`..`I150` | Item |
| units_sold | int | units | Units sold (**censored**: cannot exceed stock on hand) |
| unit_price | float | INR | Shelf price after any promotion |
| on_hand_open | int | units | Stock at opening |
| receipts | int | units | Deliveries received that morning |
| on_hand_close | int | units | Stock at close = open + receipts - sold |

Derived in ingestion: `stockout = (on_hand_close == 0)`. On these days sales under-count demand.

### raw/items.csv
item_id, category (`beverages`, `snacks`, `personal_care`, `monsoon_seasonal`), price (INR list price), pack_size (ml, g or pieces), launch_date.

### raw/stores.csv
store_id, city, region (region = city: Mumbai, Pune, Nashik).

### raw/promotions.csv (planned, known in advance)
item_id, region, date_start, date_end, discount (fraction, 0.10 to 0.30).

### raw/events.csv
date (festival start), event, kind (`festival` / `public_holiday`), source, span_days, buildup_days.

### raw/weather.parquet and raw/weather_forecast.parquet
date, city, temp_max (degC), rain_mm (mm/day), humidity (%). The forecast file holds the 14 days after the last sales day, as issued on that day (`issued`).

### raw/search.csv
date, category, search_index (0 to 100, relative interest).

### ground_truth/
`truth.parquet` (true mean demand `lam` and uncensored `demand` per store x item x day),
`items_truth.csv` (demand class, base rate, dispersion, promo elasticity), `effects.json` (every effect size used).

## Data-quality defects injected on purpose

The generator plants defects in the sales feed so ingestion has something to catch:
duplicate keys, negative units, missing prices and rows dated in the future. Counts are in
`processed/manifest.json -> dq.quarantine_reasons`.
